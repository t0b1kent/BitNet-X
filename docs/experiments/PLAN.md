# BitNet-X: план экспериментов и метрик (Фаза 3, черновик)

Статус: **только план**. Архитектура модели не меняется, пока Фаза 1 (корректный движок на Apple Silicon) не закрыта и эталон не подтверждён тестами.

## 0. Принцип разделения

| Что меняем | Что это доказывает | Чем подтверждается |
|---|---|---|
| Движок (ядра, упаковка, граф, токенизатор) | вычисления соответствуют определению | тесты `tests/`, сверка с BF16/HF эталоном |
| Модель/метод обучения | рост «интеллекта» при тех же затратах | метрики ниже на **новых** задачах |

Исправление движка **не** считается улучшением модели. Любое улучшение модели засчитывается только при воспроизводимом измерении на задачах, которых не было в обучении и подборе гиперпараметров.

## 1. Эталонная линия (baseline B0)

Условие входа в Фазу 3: все тесты Фазы 1 зелёные на M1 Pro; перплексия и генерация на CPU/Metal совпадают с HF-эталоном (BF16, fp32) в допуске.

- B0a: официальный BitNet b1.58 2B-4T, GGUF I2_S на исправленном движке.
- B0b: тот же BF16 в PyTorch (эталон точности, без квантования активаций).
- B0c: небольшая плотная fp16-модель сопоставимого размера (для оси «точность на байт»).

Фиксируем: ревизию submodule + набор патчей, хеш GGUF, seed, температуру 0, шаблон промпта, число потоков.

## 2. Метрики

**Качество (основные, на новых задачах):**
- Математика: GSM8K-подобные и свежесгенерированные арифметико-алгебраические задачи с проверяемым ответом (генератор с seed → контаминации нет); pass@1, доверительный интервал (Wilson), ≥ 500 задач на точку.
- Логика: синтетические задачи (цепочки импликаций, головоломки с проверкой SAT-решателем, глубина n=2..8) — кривая точности по глубине.
- Код: HumanEval/MBPP-подобные + свежие задачи с юнит-тестами, запуск в песочнице; pass@1.
- Языковая модель: перплексия WikiText-2 (протокол llama-perplexity, фиксированные первые N чанков) — только как проверка «не сломали».

**Эффективность (обязательны рядом с качеством):**
- Точность на единицу вычислений: accuracy / (токены × эффективные FLOPs на токен); отдельно prefill и decode.
- Задержка: prefill (ток/с) и decode (ток/с) раздельно, p50/p95; прогрев исключён.
- Память: пиковая RSS, размер весов, размер KV-кэша.
- Энергия: `powermetrics` (CPU/GPU/ANE package power) за прогон; Дж/токен.

**Правило сравнения:** улучшение принимается, если выигрыш по качеству лежит вне доверительного интервала **и** метрики эффективности не ухудшились сверх заранее заданного бюджета (по умолчанию: ≤ +20 % памяти, ≤ +50 % FLOPs/токен). Иначе фиксируется как «компромисс», а не «улучшение».

## 3. Эксперименты

### E1. Рекурсивные рассуждения (переиспользование параметров)
Гипотеза: повторное применение одного блока трансформера k раз (глубина вычисления растёт без роста числа параметров) улучшает задачи, требующие многошагового вывода.
- E1.1 Looped-блок: средние L/2 слоёв повторяются k∈{1,2,4}; веса общие. Сначала на малой модели (≈100–300M, обучение с нуля на синтетике + небольшом корпусе), потом дообучение поверх 2B.
- E1.2 Адаптивное k: простой критерий остановки (энтропия/норма изменения скрытого состояния), бюджет вычислений как явная переменная.
- Метрика: кривая «точность vs число итераций», точность на единицу вычислений против плотной модели с тем же числом FLOPs.
- Риск: обучение троичных весов с общими параметрами нестабильно → контрольные запуски fp16 того же устройства.

### E2. Адаптивная точность
Гипотеза: не все слои/токены одинаково чувствительны к грубой квантизации.
- E2.1 Чувствительность по слоям: заменить I2_S на 4–8 бит в одном слое за раз, измерить Δперплексии и Δточности; построить карту.
- E2.2 Смешанная точность: критичные слои (по E2.1), вложения, lm_head — выше точность; остальное — троичные.
- E2.3 Динамическая точность активаций (int8 → int4 на «лёгких» токенах).
- Метрика: качество vs биты на вес (эффективные), память, Дж/токен.

### E3. Малые обучаемые модули рассуждений
Гипотеза: небольшой fp16-модуль (LoRA/адаптер/«scratchpad»-голова) поверх замороженной троичной модели даёт прирост на логике/математике дешевле, чем масштабирование.
- E3.1 LoRA ранга 8–64 на синтетических рассуждениях, замороженные троичные веса.
- E3.2 Модуль вычисления (калькулятор-токены / структурные шаги), обучаемый отдельно.
- Метрика: прирост точности на новых задачах на добавленный параметр и на добавленный FLOPs.

### E4. Новые математические методы (резервное направление)
Если E1–E3 не дают результата, рассматриваем: тернарные веса с обучаемым per-group масштабом, другие распределения весов {-1,0,1}→{-2..2}, дистилляция процесса рассуждения (не только ответа). Решение о смене направления принимается по данным E1–E3.

## 4. Протокол воспроизводимости

- Один скрипт запуска на эксперимент; конфиг и seed в репозитории; результаты в `docs/experiments/results/<id>/` (CSV + манифест: коммит, хеши моделей, версия ОС, нагрузка машины до/после).
- Сравнение A/B внутри одной сессии (машина шумит); ≥ 3 повтора для скоростей; для качества — доверительные интервалы.
- Новые задачи генерируются из seed, который не использовался при разработке; отложенный тест открывается один раз.
- Скорости заявляются только с измерением; «быстрее» без A/B в одинаковых условиях не принимается.
- Любое отрицательное/нулевое попадание фиксируется так же подробно, как положительное.
